## 介绍
大语言模型，也称为 LLM，是基于大量数据进行预训练的超大型深度学习模型。底层**转换器是一组神经网络**，这些神经网络由具有**自注意力功能**的编码器和解码器组成。编码器和解码器从一系列文本中提取含义，并理解其中的单词和短语之间的关系。

LLM 的训练，本质上就是在一个高维的几何空间里，通过阅读海量文本，为词表中的每一个词（Token）找到一个最合适的“空间坐标”（嵌入向量）。在这个空间里，语义相似的词靠得近，逻辑相关的词呈现出特定的几何向量关系（比如经典的“国王 - 男人 + 女人 = 王后”）。
可以说，大模型并不是在死记硬背词表，而是把整本百科全书的语义，压缩并折叠进了一个巨大的多维空间里。


大语言模型 (LLM)，可预测一个 token 或一系列 token，有时甚至可以预测相当于多个段落的 token。请注意，词元可以是字词、子字词（字词的子集），甚至是单个字符。LLM 的预测效果比 N-gram 语言模型或循环神经网络好得多

>NLP 是任务领域，LLM 是解决 NLP 任务（以及其他任务）的一种强大工具。LLM 是 NLP 发展到一定阶段的产物，但它的能力已经超出了传统 NLP 的范畴。

## 运作机制

LLM 运作原理的一个关键因素是它们表示单词的方式。早期的机器学习使用数字表来表示每个单词。但是，这种表示形式无法识别单词之间的关系，例如具有相似含义的单词。人们采用如下方式克服此限制：使用多维向量（通常称为文字嵌入）来表示单词，从而使具有相似上下文含义或其他关系的单词在向量空间中彼此接近。

使用文字嵌入，转换器可以通过编码器将文本预处理为数字表示，并理解含义相似的单词和短语的上下文以及单词之间的其他关系，例如语音部分。然后，LLM 就可以通过解码器应用这些语言知识来生成独特的输出。



## 流程处理

```
[1. 数据预处理/嵌入] ──> [2. 自主预训练] ──> [3. 任务微调/适配] ──> [4. 预测与推理]
```

### 数据预处理/嵌入（Data Preprocessing & Embedding）
- 输入的原始文本经过切分（Tokenization）成为 Token。
- 通过词嵌入（Word Embeddings）技术将 Token 转化为数字矩阵（多维向量表示），作为 Transformer 的输入。

### 自主预训练（Pre-training / Self-Supervised Learning）

- **核心逻辑**：使用无标记的巨量文本数据进行“预测下一个 Token（Next-Token Prediction）”的自监督学习。
- **参数调整**：模型在迭代预测中对比预测结果与真实文本，不断调整内部数千亿个权重与偏差参数（Weights & Biases），以最大化正确预测的可能性。
- **结果**：在此阶段，模型掌握了语法规则、世界知识和基本逻辑思维能力，形成“基础模型（Base LLM / Foundation Model）”。

### 任务微调/适配（Adaptation & Fine-Tuning）

基础模型训练完成后，可以通过不同程度的调整来适应具体应用场景：

- **零样本学习（Zero-shot Learning）**：不提供示例，直接利用 Prompt 提示词让基础模型回答。
- **少样本学习（Few-shot Learning）**：在 Prompt 中提供几个高质量的示例指导，快速提升特定领域表现。
- **有监督微调（SFT / Fine-Tuning）**：使用特定业务领域的有标注小数据集继续训练基础模型，微调内部参数，使其适配客服、代码生成、法律咨询等专门用途。


### 预测与推理（Inference & Generation）

- 在实际应用阶段（推理），用户输入自然语言 Prompt。
- 模型将输入转换为向量，经由编码器提取语义，再由解码器结合内部学到的知识和概率分配，连续生成自然流畅的文本、代码或结构化输出。

## transformer

Transformer 是一种基于自注意力机制的深度学习神经网络架构，彻底改变了自然语言处理和整个人工智能领域。

Transformer是一套基于自注意力机制的架构，它让每个 Token可以直接关注所有其他 Token，从而彻底解决了RNN 的串行计算和长距离遗忘问题。


## 数据结构

三条独立的信息流

| 信息流                     | 存储位置                                 | 生命周期               | 作用                                  |
| ----------------------- | ------------------------------------ | ------------------ | ----------------------------------- |
| **映射规则**                | `vocab.json`, `merges.txt`           | 训练前由BPE生成，**永久固定** | 告诉你"字符串"对应哪个"ID"                    |
| **词向量（Embedding）**      | `model.ckpt` 中的 `token_embedding` 矩阵 | 随模型训练**不断更新**，最终定型 | 告诉你"ID"对应哪一串"浮点数"<br>形状\[V词表大小,d向量] |
| **模型权重（Attention/FFN）** | `model.ckpt` 中的其他参数                  | 随模型训练**不断更新**，最终定型 | 决定"向量"经过计算后变成什么"结果"                 |

如果只有前两个文件（vocab + merges）而没有 model.ckpt，你只能把汉字转成ID，但永远无法让AI理解或生成任何有意义的文本。

在LLM中词嵌入层的数据结构本质上是一个矩阵，形状为\[V, d]。
比如：
- V词表大小：比如 50,000 个不同的词。
- d（嵌入维度）：比如 768 个浮点数。
- Token ID：可以理解为矩阵的“行索引（Index）”；
- 模型参数量 = V × d = 50000×768 = 38400000

在自然语言处理中，模型接收到的原始输入是离散的整数（Token ID）。嵌入层（Embedding Layer）的作用就是将这些整数 ID 转换为连续的浮点数向量。因此，嵌入层输出的向量，正是后续神经网络（如 Transformer）进行计算时的“初始特征表示”。

## token
神经网络底层做的是矩阵乘法，输入必须是数字。所以无论你输入什么语言，第一步一定是把文字转成一串离散的数字 ID，这个过程的产物就叫 **Token**。

结论是：存在一种比"单词"更科学的粒度，同时兼顾效率和语义——这就是 Token。

Token → Embedding：从离散 ID 到连续语义空间
Embedding（词嵌入）。把每个离散的 Token ID 映射到一个高维连续向量空间，用向量的方向和长度来表达语义。
**Embedding 模型的跨语言能力**——"Karpathy"和"卡帕西"在向量空间中是靠近的，说明模型学到的不是死板的字面匹配，而是更深层的语义表征。


token的创建
tokenization方法(分词)
分词的目的是将复杂问题转化为数字问题，即指将文本的非结构化数据转化为【结构化的数据】，这样就可以将数据转化为数学问题。

分词重点：如何获得一种理想的切分效果，使文本中所有的token都具有正确的语义，并且不会存在遗漏的问题。

从上述Tokenization（分词）的任务内容可知，其是为数值化作准备，数值化的过程必然需要映射，而映射又需要一个目标集合或者说**映射表(词表Vocabulary)**。

### token使用步骤
- 特征提取：Tokens用于提取输入机器学习模型的特征。特征可能包括Tokens本身、Token的频率、Token在句子中的位置等。例如，在情感分析中，某些Tokens的出现可能会强烈地表明正面或负面的情感。
- 矢量化：在许多 NLP 任务中，使用词袋（BoW）、TF-IDF（词频-反向文档频率）或词嵌入（如 Word2Vec、GloVe）等技术将词组转换为数字向量。这一过程将文本数据转化为机器学习模型可以理解和处理的数字。
- 序列建模：在语言建模、机器翻译和文本生成等任务中，Tokens会被用于序列模型，如递归神经网络（RNN）、长短期记忆网络（LSTM）或Transformers。这些模型通过理解上下文和Token出现的可能性来学习预测下一Token序列。
- 训练模型：在训练阶段，模型会收到Token化后的文本和相应的标签或目标（如分类任务的类别或语言模型的下一个Token）。模型会学习Token与所需输出之间的模式和关联。
- 上下文理解：BERT 和 GPT 等高级模型使用Tokens来理解上下文，并生成能捕捉特定上下文中单词含义的嵌入。这对于同一个词根据其用法可能具有不同含义的任务来说至关重要。


### 三种Tokenization(分词器)方法

按照切分的粒度可以将Tokenization分为三类
- 一是按词粒度来分
词粒度是一种自然而然的方法，因为人类对于自然语言文本的理解就是按照这种方式进行切分的
基于词表和规则的分词方法可以分为3种，即1、 前（后）向最大匹配法；2、最短路径分词法；3、基于 N-Gram LM 的统计词频分词法。
工具/方法：NLTK、SpaCy，中文的 jieba、HanLP
- 二是按字符粒度来分
字符粒度是按某一种语言最小符号来进行切分的。简单说就是英文（拉丁语系）以字母为单位，中文日文韩文等则是以字为单位进行切分。
缺点比较严重，现实中实现比较少
- 三是按 subword（子词粒度来分）。
subword粒度切分是一种折中的方法，但只适用于英文等拉丁语系的语言，对于中文来讲，由于不能将某一个字拆分为偏旁部首和字根，没有意义。

工具/方法
  - BPE(字节对编码):是一种数据压缩方法，BPE 迭代地合并最频繁出现的字符或字符序列；
  - WordPiece：WordPiece主要应用于解决日语和韩语语音问题。它与 BPE 相同点：每次从统计语料中选取出两个新的子词进行合并。它与 BPE 最大区别在于选择两个子词进行合并的原则：BPE 按频率，WordPiece 按能够使得 LM 概率最大的相邻子词加入词表。
  - UniLM：与 WordPiece类似同样使用语言模型来挑选子词，UniLM会保留那些以较高频率出现在很多句子的分词结果中的子词，因为这些子词如果被丢弃，其损失会很大。

### 词汇表的创建流程

```
"你好世界" → [124, 356, 789, 234]
```
这个映射关系存储在词表（vocab.json / merges.txt）中。它不是人工手动编写的，而是通过算法从海量文本中"学习"出来的。

目前主流大模型（GPT、LLaMA、DeepSeek）大多使用 BPE（Byte-Pair Encoding，字节对编码） 或其变体来构建词表。

**词汇表的生成过程**
- 阶段一：准备"语料库"（原材料）
>这个语料库通常有几十TB，覆盖了你希望模型能处理的几乎所有语言和领域。

- 阶段二：BPE算法迭代合并（核心）
  - Step 1：拆分成最小单元（字符级）
  > 把语料库中的所有文本拆成最基础的字符（对于英文是字母+标点，对于中文是单个汉字或Unicode字节）：

  - Step 2：统计相邻"字符对"的出现频率
  - Step 3：合并频率最高的一对
  - Step 4：重复迭代直到预设的阈值(5w/10w...)
  >经过成百上千次合并，最终词表里既有高频词汇（如 "the"、"你"、"好"），也有常见的词根词缀（如 "ing"、"ed"、"tion"），还有特殊符号（如 <|endoftext|> 表示结束）。

- 阶段三：词表的最终形态
训练完成后，你会得到两个文件：

| 文件             | 内容                                      | 作用             |
| -------------- | --------------------------------------- | -------------- |
| **vocab.json** | `{"你": 123, "好": 456, "世界": 789, ...}`  | 字符/词 → ID 的映射  |
| **merges.txt** | `[("h","e","he"), ("你","好","你好"), ...]` | 记录合并顺序（用于解码还原） |
对于绝大多数新词（包括每年新增的网络热词），大模型凭借其强大的上下文理解能力，依然能准确推断含义。


映射表（词表）一旦确定，永久固化，极少变更。增加新词不是通过修改词表，而是依赖BPE的自动拆解机制。
- 新词处理：被拆成更小的已知单元，模型通过上下文理解含义。
- 词表变动：只有在训练新一代模型时才会重新设计。
- 如果强行加词：新token的向量无法与已有权重良好对齐，效果反而不如拆解。
>词汇表更新问题：模型都是通过固定的词汇表训练的，贸然进行更新，会导致模型参数间的关系失效；

## Embedding(嵌入)
Embedding（嵌入）在机器学习和自然语言处理领域中是一个常见的概念，通常指的是将数据映射到一个低维度的向量空间的过程。在自然语言处理中，最常见的是词嵌入（Word Embeddings）。

嵌入(Embeddings)是Tokens的高级向量表示。它们试图捕捉Tokens之间最细微的差别、联系和语义。每个嵌入通常是神经网络计算的向量空间上的一系列实数。

简而言之，输入文本被转换为Tokens。每个Token被赋予一个Token ID。这些Token ID在模型训练时，可用于创建Embedding，以便在复杂的模型中进行更细致的数字表示。LLM模型的输入正是这些Embedding向量
>Embedding向量：存储在模型的`model.ckpt` 中的 `token_embedding` 矩阵中，随者模型训练完成而定型；
>计算机能理解数字，并通过数字进行运算。而Embeddings才是 LLM 的 "真正输入"
>嵌入实际上是LLM模型权重的一个子集。它们通常是与嵌入层（在Transformer等模型中）（通常是第一层）相关的权重。


**工作原理**
- 高维转低维：传统方法用[独热编码](机器学习/机器学习-算法.md#独热编码(One-Hot%20Encoding))（One-Hot Encoding）表示词语，维度极高且孤立。Embedding 将其压缩到固定大小的低维空间（如几百到几千维）。
- 捕获语义：通过深度学习模型在海量文本上进行训练，学习字词之间的上下文关联。
- 数学计算：通过计算向量之间的余弦相似度（Cosine Similarity），就能精准判断两句话或两个词的相似程度，告别死板的字面匹配。

**Token到Embedding的转换方法和工具**
- Word2Vec ：一种神经网络模型
- GloVe：一种无监督学习算法，可用于单词表示的全局向量
- FastText：Word2Vec的扩展；生成词和子词向量的模型，速度较快，但嵌入质量不如 BERT 等模型
- BERT： 基于 Transformer 的预训练模型，通过掩码语言模型（MLM）和下一句预测（NSP）任务生成上下文感知的词嵌入。
- ELMO: 一种深度双向 LSTM 模型。
- Sentence-BERT：基于 BERT 的模型，专门用于生成句子级别的嵌入，适合高效相似度计算。

### 嵌入层
在深度学习中，嵌入层是神经网络模型中的一层，用于学习和应用嵌入。

对于自然语言处理任务，嵌入层通常用于将离散的词汇映射到连续的词嵌入向量。这样的嵌入层通常是模型的第一层，其输出将作为输入传递给后续层。这些嵌入向量是通过训练过程中学习得到的，以便更好地适应任务的特定语境。

Embedding不是“词的权重”，而是“词在向量空间中的数学表示”；从模型实现角度，它又是一组可训练参数。训练时是变量，通过 Loss 和梯度不断调整；训练完成后作为模型参数固定下来，在推理时可以看作常量。

>嵌入层在物理上就是一个形状为 \[词表大小, 隐藏层维度] 的巨大二维矩阵。矩阵中的每一个浮点数都是一个权重参数，因此它的总参数量确实是“词表大小 × 隐藏层维度”
>再神经网络中，**嵌入层通常作为输入层的一部分**；在这层进行token->embedding查表获取词向量；


**示例**
假设我们有一个词汇表，其中有5个单词："apple"、"banana"、"orange"、"grape"、"kiwi"，并且它们分别被编号为1、2、3、4、5。我们决定使用3维的向量表示每个单词。
嵌入层的目标是将这5个单词的编号映射到3维的实数向量：
```
- "apple" 可以被映射为 [0.1, 0.2, 0.3]
- "banana" 可以被映射为 [0.4, 0.5, 0.6]
- "orange" 可以被映射为 [0.7, 0.8, 0.9]
- "grape" 可以被映射为 [0.2, 0.3, 0.4]
- "kiwi" 可以被映射为 [0.5, 0.6, 0.7]
```

这样，我们就将每个单词用一个3维的实数向量表示了。这些向量在机器学习模型中可以用于学习单词之间的语义关系和模式，从而更好地理解和处理文本数据。


### Embedding如何训练
这里主要说的是大模型文本嵌入/词嵌入；

现代大模型（GPT/BERT）一般不用独立的词嵌入模型了，而是**神经网络模型**通过大规模文本进行**自监督学习**得到每个词的向量表示。词嵌入不再有自己的损失函数，它融入了整个语言模型的损失函数中。

现代大模型的训练目标是“预测下一个词”（Causal LM），损失函数是交叉熵损失（Cross-Entropy Loss）：$L = - \sum_{i=1}^n y_i \log(\hat{y}_i)$
>模型只是在利用文本自身的顺序结构作为标签。数据本身就是自己的老师。当前时刻的输入是“上文的特征”，当前时刻的下一个词就是“标签”。

### LLM词嵌入示例

当我们用 GPT 做预训练时，它的任务不是识别猫狗，而是“预测下一个词”。
假设输入句子是：“我 喜欢 吃 苹果”
我们把这句话处理成训练样本：

| 时间步 | 输入（上文） | **模型预测目标（标签 $y$）** | **模型输出（预测 $\hat{y}$）** |
| --- | --- | --- | --- |
| t=1 | `[我]` | 预测 **“喜欢”** | 模型算出一个概率分布 `[0.1, 0.7, 0.2, ...]` |
| t=2 | `[我, 喜欢]` | 预测 **“吃”** | 模型算出下一个概率分布 |
| t=3 | `[我, 喜欢, 吃]` | 预测 **“苹果”** | 模型算出下一个概率分布 |

标签值就是输入文本里的“下一个真实的词”。
- 在 t=1 时刻，标签值 $y$ 是 “喜欢”（One-hot 编码，即“喜欢”这个词对应的位置是1，其他全是0）。
- 在 t=2 时刻，标签值 $y$ 是 “吃”。
- 在 t=3 时刻，标签值 $y$ 是 “苹果”。

损失函数计算过程
- 模型读入 \[我, 喜欢, 吃]，计算出一个预测概率向量（预测值）。
- 拿出真实的 \[苹果]，把它变成 One-hot 向量（标签值）。
- 计算这两个概率分布之间的交叉熵。
- 如果模型预测 \[苹果] 的概率很低，交叉熵值就会很大，说明模型“意外”了；梯度下降算法就会调整模型权重，让下次再看到 \[我, 喜欢, 吃] 时，能正确预测出 \[苹果]。

>损失函数也是在输出层后进行计算的，后续就开始反向传播、梯度下降、权重调整、词向量更新；

## LLM超参数

| 核心概念 | 通俗比喻 | 数学/技术定义 | 谁决定的？ |
| --- | --- | --- | --- |
| **1. 词表大小 (V)** | **常用字库**：大楼里能识别的所有汉字总数（比如新华字典收了1.2万个字）。 | 分词器（Tokenizer）里不同Token的数量。 | 训练前固定，由BPE算法在语料上跑出来的。 |
| **2. 嵌入维度 (d)** | **每个人的档案厚度**：为了描述清楚一个词，要用多少个特征（比如身高、体重、籍贯……一共1280项）。 | 每个Token被映射成的浮点数向量的长度。 | 模型设计者设定（通常 768 ~ 16384）。 |
| **3. 层数 (L)** | **大楼高度**：信息要往上穿透多少层处理层（比如20层楼）。 | Transformer Decoder 的堆叠数量。 | 模型设计者设定（通常 12 ~ 120 层）。 |
| **4. 每层神经元数 (FFN维度)** | **每层楼的办公桌数量**：这一层能并行处理多少条信息。 | 前馈网络（FFN）的中间层维度（通常为 4d）。 | 模型设计者设定（通常为嵌入维度的4倍）。 |
| **5. 输出维度** | **最终报告格式**：模型最后要输出什么格式的结果。 | 对于分类任务：类别数；对于生成任务：词表大小 V。 | 由任务决定（生成式LLM固定为 V）。 |
| **6. 上下文长度 (T)** | **大楼能同时阅读的纸张长度**：模型一次能“看”多少个Token。 | 最大序列长度（如 2048 或 1M）。 | 由位置编码和显存决定。 |
| **7. 模型参数量** | **大楼总建材用量**：所有层、所有矩阵里的数字总个数。 | 所有权重矩阵的数字个数之和。 | 由上述 V, d, L 计算得出。 |
| **8. 输入长度** | **你实际塞进来的纸张长度**：你提问时，这句话有几个字。 | 当前输入序列的实际Token数（≤ 上下文长度）。 | 由你的输入决定。 |


真实模型示例：LLaMA 7B 的完整参数表

|参数名称|符号|具体数值|解释|
|---|---|---|---|
|**词表大小**|V|32,000|支持中英文等多语言。|
|**嵌入维度**|d|4,096|每个Token用4096个浮点数描述。|
|**层数**|L|32|垂直堆叠了32层Transformer。|
|**每层神经元数 (FFN)**|ffn_dim|11,008|约等于 4,096 × 2.6875（LLaMA的独特比例）。|
|**输出维度**|-|32,000|最后输出层要映射回词表大小，预测下一个词。|
|**上下文长度**|T_max|2,048（原始） / 4k（升级）|模型初始化时最多支持2048个Token。|
|**输入长度**|T_in|**取决于你**|你问“你好”，T=2；你问长文，T=2000。|
|**模型总参数量**|Params|**约 70亿**|所有矩阵数字加起来 ≈ 6.7B（含嵌入层）。|


数学关系
1. 嵌入层参数量：$\text{Embedding Params} = V \times d = 32,000 \times 4,096 \approx 1.3亿$
2. 单层Transformer参数量（简化版）：$\text{Layer Params} \approx 4 \times d^2 + 2 \times d \times ffn\_dim$
代入 LLaMA：$4 \times 4096^2 + 2 \times 4096 \times 11008 \approx 67M + 90M \approx 1.57亿$
>	$4 \times d^2$：多头注意力的结构包含 4个权重矩阵(Query映射、Key映射、Value映射、输出映射)
>	2×d×ffn_dim：前馈网络由 2层全连接层 组成（即两个线性层），W₁（第一层升维/降维），W₂（第二层投影回d）
3. 模型总参数量：$\text{Total} \approx \text{Embedding} + L \times \text{Layer Params} \approx 1.3亿 + 32 \times 1.57亿 \approx 51亿$
（这里是简算；官方数据：70亿，具体需要看开源项目）
>	所有偏置项（bias）：64个矩阵 × 平均约4,096个偏置 ≈ 数百万；总量里面没有加进去；还有其他一些如LayerNorm，或其它层参数比较少的，没加进去；

4. 上下文长度与输入长度的关系：$\text{输入长度} \leq \text{上下文长度}$
  - 输入长度=2时，只算2个Token，计算量极小。
  - 输入长度=2048时，达到上限，再长就会报错或截断。
  - 上下文长度限制：$T_{\text{max}} = \min\left( \text{位置编码最大范围}, \frac{\text{单卡显存}}{\text{每个Token占用的显存}} \right)$
  >上下文长度没有固定计算公式，它是一个人为设定的“上限值”。一旦设定后，它直接决定计算量和显存占用的增长幅度：

## QA
### Q模型的权重、嵌入维度多少比较合适
A词嵌入维度 ≈ 词表大小的 4 次方根。通常取值在 768 到 4096 之间，具体取决于模型参数量级和训练数据量。
在深度学习中，嵌入层（Embedding Layer）的参数量 = 词表大小（V）× 嵌入维度（d）。

| 模型规模                | 典型嵌入维度     | 词表大小（约） | 嵌入层参数量    | 占总参数比例      |
| ------------------- | ---------- | ------- | --------- | ----------- |
| **小模型（BERT-base）**  | 768        | 3万      | 2.3亿      | **~25%**    |
| **中模型（GPT-2）**      | 768 ~ 1024 | 5万      | 5亿        | **~15%**    |
| **大模型（GPT-3 175B）** | 12288      | 5万      | **61亿**   | **仅 ~3.5%** |
| **超大模型（传闻 GPT-4）**  | ~16000+    | 10万     | **160亿+** | **< 2%**    |
